Variables reference#

Every setting this cluster is built from, with the value it has today. Ansible reads group_vars/all.yml, hosts.yml and each role’s vars/ or defaults/; ArgoCD reads kubernetes-services/values.yaml. A few settings exist in both worlds and must agree: they are marked SYNC here and in the files.

Variable

Value

Description

ansible_account

ansible

The account Ansible uses on every node (created by the RK1 cloud-init seed, or by pb_add_nodes.yml)

tpi_user

root

SSH user on the Turing Pi BMC

tpi_images_path

/mnt/sdcard/images

Where OS images are staged on the BMC’s SD card before tpi flash

/root/bin (from $BIN_DIR; $HOME/bin without it)

Where the tools role installs helm, kubectl, kubeseal, hubble, argocd and the port-forward scripts: a volume, so it survives a devcontainer rebuild

k3s_minor

v1.34 (read from k3s.minor in values.yaml)

The K3s minor line the cluster follows. Edit it in values.yaml, not here

do_flash

false

Whether the flash role runs; true when flash_force (or force_flash) is passed, or set directly with -e do_flash=true

local_domain

.lan

Suffix the known_hosts role adds to a node name to look up its addresses

known_hosts_files

~/.ssh/known_hosts, /etc/ssh/ssh_known_hosts

Files the known_hosts role keeps current. The system-wide one is what claude-sandbox reads, as its $HOME is a fresh tmpfs

control_plane

node02

The (single) control plane node

standby_control_plane

node03

Warm-standby control plane: the node a restore goes onto (Recover the control plane). The cluster tag taints it node-role.kubernetes.io/standby-control-plane:PreferNoSchedule and removes that taint from any other node. Empty for none

k3s_api_name

k3s.lan

Stable DNS name for the Kubernetes API, a record on the router that resolves to the control plane: the router’s DHCP template points it at control_plane’s lan_ip (Manage the router’s DNS and DHCP). Agents join it, it is a tls-san on the server certificate and the kubeconfig uses it, so moving the control plane means changing control_plane and pushing the router’s template. Every address it resolves to must be the control plane’s

dns_router

root@192.168.1.1

SSH target (user@host) of the OpenWrt router (dnsmasq, uci). Used by just k3s-api-dns <ip> to point k3s_api_name at the control plane, by the control plane’s daily router backup (etcd_backup_router) and by pb_router.yml, through the router host in hosts.yml (Back up and recover the router)

router_dns_servers

[1.1.1.1, 1.0.0.1]

The upstream DNS servers the router’s dnsmasq forwards to (Manage the router’s DNS and DHCP)

router_dhcp_hosts

(list)

The router’s static leases matched by MAC, for devices whose hostname this repo doesn’t set (the Turing Pi BMC, node01, the Raspberry Pis, …): name (optional), ip and macs. Hosts in hosts.yml with lan_ip are reserved by name instead (Manage the router’s DNS and DHCP)

etcd_backup_age_recipient

(age public key)

The key the nightly etcd backup is encrypted to; the private key is kept offline. Empty makes the backup fail without uploading. SYNC: offsite_backup.age_recipient (scripts/check-age-recipient, run by just check, fails if they differ)

cluster_domain

gkcluster.org

Domain of every ingress host

domain_email

(an address)

Let’s Encrypt registration address for cert-manager

admin_emails

(list)

GitHub-linked addresses mapped to ArgoCD admin in the Ansible-rendered ArgoCD config. SYNC: admin_emails in values.yaml

repo_remote

https://github.com/gilesknap/tpi-k3s-ansible.git

The repo ArgoCD deploys from

repo_branch

main

The branch ArgoCD tracks. The root Application passes it to every child app (Develop and ship a change)

nvidia_gpu_node, intel_gpu_node

false

Defaults for the per-node GPU flags below

cluster_install_list

[argocd]

What the cluster role installs itself; everything else is ArgoCD’s

k8s_data_dirs

prometheus and grafana on node04 (/var/lib/k8s-data/...); scrap-backup-copy and jellyfin on nuc2 (/home/k8s-data/...)

Host directories behind the local-nvme PVs, each with node, path, owner, group and mode. The k8s_data_dirs role creates them and never deletes one. SYNC: node and path with local_storage in values.yaml

Command-line overrides#

Passed with -e to ansible-playbook. None of them is stored anywhere: each applies to that run only.

Override

Playbook

Effect

-e do_flash=true

pb_all.yml

Run the flash role: flashes any Turing Pi node that does not answer SSH

-e flash_force=true

pb_all.yml

Also re-flash nodes that do answer, and allow the wipe of an RK1 NVMe that has a partition table. Use with --limit turingpi,<node>

-e k3s_force=true

pb_all.yml

Uninstall and reinstall K3s on the targeted nodes

-e k3s_version=v1.34.13+k3s1

pb_all.yml

Install that exact release; it must be on the k3s_minor line

-e reboot_now=true

pb_all.yml

After update_packages, drain and reboot each node that needs it, one at a time, instead of leaving it to kured. Never reboots a workstation

-e repo_branch=<branch>

pb_all.yml --tags cluster

Point ArgoCD at a branch (what just switch-branch does)

-e claude_pubkey_state=absent

pb_all.yml --tags claude_key

Remove the Claude sandbox key from the nodes instead of adding it

-e claude_ansible_pubkey_path=<path>

pb_all.yml

Use a different public key file than /root/.config/claude-ssh/id_ed25519.pub

-e '{"known_hosts_files": ["~/.ssh/known_hosts"]}'

pb_all.yml

Skip the system-wide known_hosts file when not running as root

-e ansible_user=<user> -K

pb_add_nodes.yml

The existing sudo-capable account on a machine that has no ansible account yet

-e wipe_local_data=true

pb_decommission.yml

Also delete /home/k8s-data and /var/lib/k8s-data: every local-nvme PV’s data. Destructive

List of name, protocol (tcp/udp), ports (port or min-max) and target; each publishes ports on the VPS and relays them to the same ports on target. The VPS’s allowPorts and firewall must match

enable_kyverno / kyverno.chart_version

false / 3.9.1

Kyverno is off: the app never settled to Synced on its CRDs, and no policies were in use

local_storage.<name>

grafana and prometheus on node04; scrap_backup_copy and jellyfin on nuc2

One static local-nvme PV each: node, path, capacity and the claim_namespace/claim_name it is pre-bound to (Storage). SYNC: k8s_data_dirs

The root Application passes repo_branch in from Ansible, so the copy in values.yaml is only a default for helm template runs; switch branches with just switch-branch <branch>.

The nfs.* values feed the static backup, Minecraft and scrap volumes, Jellyfin’s media and the off-site backup’s mounts, and the etcd_backup role reads them from values.yaml for its NAS mount. The nfs_csi.* values configure the dynamic NFS StorageClasses separately.
