Deploy scrap#

scrap is a personal knowledge store: a web app (installable as a PWA) plus an MCP endpoint at /mcp for AI coding tools. The application and its Helm chart live in the scrap repository. This repository provides the cluster wiring:

  • An ArgoCD Application (kubernetes-services/templates/scrap.yaml) that deploys the chart from a git tag, with a NetworkPolicy, a local-disk data volume, a nightly backup CronJob and Claude ingest (enabled in this deployment).

  • An ingress for scrap.<domain> gated by oauth2-proxy, plus a second /mcp-only ingress without oauth2-proxy (kubernetes-services/additions/scrap/), disabled by default (see below).

  • A local_storage.scrap volume and a k8s_data_dirs entry for the data directory.

  • Public pages: the chart’s public section serves the pages marked Public as a static site at pages.<domain>, from its own scrap-public namespace (see Public pages).

scrap has no login of its own, so access control is layered in front of it.

Authentication layers#

Path

Layer 1

Layer 2

Web UI / PWA

Cloudflare Access (email one-time PIN)

oauth2-proxy GitHub login, limited to admin_emails

/mcp

Cloudflare Access service token (CF-Access-Client-Id / CF-Access-Client-Secret headers)

scrap bearer token

pages.<domain>

None: a Cloudflare Access Bypass application, as the site is public

None: static files only, nothing can reach scrap

The /mcp path cannot use oauth2-proxy because MCP clients cannot complete a browser login. It has its own Ingress, and nginx routes to the most specific path, so /mcp skips the oauth2 annotations of the main ingress.

Note

Hosted MCP connectors that run from a vendor’s cloud (for example a chat app’s custom connector) cannot send Cloudflare service-token headers, so they cannot reach /mcp through this design.

Warning

The /mcp Ingress is gated by mcp_ingress_enabled in kubernetes-services/templates/scrap.yaml. Keep it true only while the scrap chart targetRevision is a release with SCRAP_MCP_TOKEN bearer auth (0.2.0 or later) and mcp.tokenSecret is set. Until then Cloudflare would be the only protection on /mcp, and ingress-nginx is reachable directly (LAN or split DNS) bypassing Cloudflare.

The NetworkPolicy admits only the ingress-nginx namespace, so nothing else in the cluster can reach the pod or forge identity headers.

Deploy#

  1. Make sure the data directory exists on the pinned node: ansible-playbook pb_all.yml --tags servers runs the k8s_data_dirs role, which creates /home/k8s-data/scrap.

  2. Seal the Claude API key into the scrap-secrets SealedSecret (ingest is enabled, so this is required). Follow kubernetes-services/additions/scrap/README.md and Manage Sealed Secrets. The file is kubernetes-services/additions/scrap/templates/scrap-secret.yaml.

  3. Commit, then let ArgoCD sync. Do this only after step 2: until the SealedSecret exists the pod sits in CreateContainerConfigError because it references the missing scrap-secrets Secret.

  4. For /mcp, seal SCRAP_MCP_TOKEN into the same Secret, point mcp.tokenSecret at it and set mcp_ingress_enabled: true. Use a scrap release of 0.2.0 or later.

Cloudflare configuration#

In the Cloudflare dashboard, following Expose Web Services via Cloudflare Tunnel:

  1. Add a public hostname scrap.<domain> on the tunnel pointing at ingress-nginx.

  2. Make sure an Access application covers the whole host with an email one-time-PIN policy (a wildcard application is enough). Use a long session duration so the PWA is not constantly challenged.

  3. Add a more specific Access application for scrap.<domain>/mcp with a Service Auth policy and a service token. Store the token safely.

  4. Confirm the more specific application wins for /mcp.

Public pages#

scrap can publish the pages you mark Public to a static site at https://pages.<domain>, open to anyone. The scrap chart’s public section (in kubernetes-services/templates/scrap.yaml) runs it in a namespace of its own, scrap-public: one pod with nginx, which serves the site, and an upload receiver that scrap pushes each public page to. Nothing on the public side can reach scrap. See the scrap deployment guide for the design.

This repository provides:

  • the scrap-public namespace (additions/scrap/templates/public-namespace.yaml), labelled Pod Security restricted. The chart’s public.createNamespace is left false, and Argo CD’s CreateNamespace=true creates only the Application’s own namespace (scrap), so the namespace is a manifest here;

  • the upload token, a SealedSecret scrap-publish (key token) sealed twice, once for each namespace, because a pod reads only its own namespace’s Secrets: scrap-publish-secret.yaml (scrap) and scrap-public-publish-secret.yaml (scrap-public). Both must hold the same token; kubernetes-services/additions/scrap/README.md has the command that seals a new one into both;

  • an Ingress for pages.<domain> (the chart’s public.ingress) on the nginx class with the wildcard certificate, without the oauth2-proxy annotations. Only nginx is on it; the receiver never is;

  • public.networkPolicy.webFrom, which admits only the ingress-nginx namespace to nginx. The chart’s NetworkPolicy admits only scrap’s pods to the receiver, and denies all egress from the namespace.

The image is ghcr.io/gilesknap/scrap-public; its package must be public on GitHub (or the cluster given a pull secret), otherwise the pod cannot pull it.

The site is held in an emptyDir, so it starts empty when the pod moves; scrap checks the receiver’s manifest at start and every 10 minutes and pushes what is missing.

Cloudflare for the public site#

The wildcard Access application covers every subdomain, so without more configuration readers of pages.<domain> meet a login page. In the Cloudflare dashboard:

  1. Add a public hostname pages.<domain> on the tunnel pointing at ingress-nginx, as for scrap.<domain> (Expose Web Services via Cloudflare Tunnel).

  2. Add an Access application for pages.<domain> with a policy whose Action is Bypass and Include Everyone, as in Bypass application for API endpoints. The more specific application takes precedence over the wildcard.

Notes on the unauthenticated path#

  • Kubernetes probes talk to the pod directly, so no health endpoint needs to be exposed through ingress.

  • oauth2-proxy sets a cookie on .<domain> shared by all services. Its default lifetime is 168 hours with no refresh, and the cookie is SameSite=Lax. After it expires, background fetch calls from the PWA (such as an offline queue replay) get a redirect to the login page instead of a response. Open the app in the browser to log in again, then the queue replays.

  • A cross-site top-level POST (for example an Android share target started from another app) does not carry a Lax cookie, so the first share after expiry may land on the login page. Verify this on your device.

  • nginx does not strip client-supplied identity headers on the /mcp path. Do not rely on any identity header there until scrap can be told which header to trust.

Verify#

kubectl -n scrap get pods,pvc,networkpolicy

  • The PVC is bound to the local volume on the pinned node.

  • A browser with no cookies is sent to Cloudflare, then GitHub.

  • /mcp without the Cloudflare headers is refused at the edge; with them but without the scrap token it returns 401; with both it works.

  • A capture from the phone appears, and the nightly backup CronJob completes.

For public pages:

kubectl -n scrap-public get pods,ingress,networkpolicy,secret

From outside your private network:

  • https://pages.<domain>/ returns 200, with no Cloudflare Access redirect.

  • https://pages.<domain>/v1/manifest returns 404: the receiver is not on the Ingress.

  • In scrap, /api/health shows enabled: true in its publish block.
